# Japanese Academic Writing — 日本語学術論文執筆・校正 Skill

日本語の学術論文（機械工学・制御工学・ロボット工学・メカトロニクス）の執筆支援と校正をおこなうスキル。対象は査読付き学術論文・学会発表原稿・技術報告書で、文書形式はLaTeX（`.tex`/`.bib`）。文体統一・文法表記・文献・図表・数式の5観点で校正し、修正提案は必ず「修正例＋理由」を添えておこなう。本スキルはプロジェクトの `.github/copilot-instructions.md` をブラッシュアップしてスキル化したものである。

## When to Use

次の依頼を受けたときに使う:

- 日本語の学術論文・学会原稿・技術報告書の執筆・推敲・校正
- LaTeX文書（`.tex`/`.bib`）への文体統一、文献・図表・数式の不備チェック
- 日本語文章の書き直し提案（複数案の提示）
- 査読・投稿前の自己チェック

次の場合は使わない:

- 英語論文の校正（`research-paper-writing` を使用する）
- コードの修正やビルド環境の構築のみ
- 日本語のビジネス文書・広報文など学術文体でない文書

## Prerequisites

- 校正対象の `.tex` / `.bib` ファイルがワークスペース内に存在すること
- ビルド検証をおこなう場合: LaTeXツールチェーン（`latexmk`、または `platex` + `pbibtex` + `dvipdfmx`）が利用可能であること（本リポジトリではDevContainer内の `paperist/alpine-texlive-ja` を使用）
- 図表の保存先は慣例として `./figures/` と `./tables/`

## How to Run

校正の全体フローは **Procedure** に従う。単発の修正依頼（「この一文を直して」など）の場合は該当箇所のみ対応し、チェックリスト全項目の実施は不要。ビルドが必要な検証（文献・数式の参照整合性など）は `terminal(command="latexmk -silent main.tex")` でおこなう。

## Quick Reference

| 目的 | 方法 |
|---|---|
| `.tex`/`.bib` の列挙 | `search_files(pattern="*.tex")` / `search_files(pattern="*.bib")` |
| 「です・ます」調の検出 | `search_files` で `です。` / `ます。` / `でした。` を検索 |
| 未引用bib文献の検出 | `terminal` で `\cite{...}` を全抽出し、bib内のkeyと突合 |
| 図配置 `[h]` の検出 | `search_files(pattern="\begin{figure}")` で配置オプションを確認 |
| ビルド検証 | `terminal(command="latexmk -silent main.tex")` |
| bib警告の確認 | `terminal(command="pbibtex main")` の未定義・未使用警告を確認 |

## Procedure — 校正の進め方

1. **対象の把握** — `search_files` で `.tex`・`.bib` を列挙し、本文ファイルの構成（`\input`/`\include`）、bibファイルの有無、`\bibliography`・`\bibliographystyle` の有無を確認する
2. **ビルド確認** — `terminal(command="latexmk -silent main.tex")` を実行し、エラーなくPDFが生成されることを確認する。エラー・警告があれば先に報告する
3. **文体チェック** — である調の統一（チェックリストA）
4. **文法・表記チェック** — チェックリストA
5. **文献チェック** — チェックリストB
6. **図表チェック** — チェックリストC
7. **数式・記号チェック** — チェックリストD
8. **報告** — 指摘を「修正済み」と「要修正（提案）」に分け、重大度順（文献欠落・誤字 → 文体の揺れ）で整理して提示する

各ステップは終了条件を満たしてから次に進む（例: ステップ2は「エラーなしでPDFが生成される」こと）。

## チェックリスト

### A. 文法・表記

- [ ] である調で統一されている（「です」「ます」の混入を検出し「である」に修正する）
- [ ] 一文が100字以内（超えた文は2文に分割する案を提示する）
- [ ] 段落が1主題に集中し、1文だけの段落がない（目安: 2〜4文・100〜300字程度）
- [ ] 時制が一貫している（既知の事実・手法の説明は現在形、実験の実施・結果は過去形）
- [ ] 単位がSI単位系で統一され、数値と単位の間は半角スペース（`10 mm`）。単位・関数は本文・数式中ともローマン体（`\mathrm{}`）
- [ ] 全角・半角の揺れがない（数字、カッコ、ピリオド）
- [ ] 用語の表記揺れがない（例: センサ／センサー、パラメータ／パラメーター）
- [ ] 主述のねじれ・助詞の誤用がない

### B. 文献（引用・参考文献）

- [ ] bibファイル内の文献がすべて本文で引用されている（未引用文献には、最も自然な引用箇所を提案する）
- [ ] 引用コマンドが一貫している（natbib使用なら `\citep`/`\citet`、それ以外なら `\cite` に統一）
- [ ] 本文で言及されているのにbibに存在しない文献がない
- [ ] bibファイルが存在しない場合: 引用文献を含むbibファイルを作成し、`\bibliography{...}` コマンドを追記するよう提案する
- [ ] 過去5年以内の研究が2件以上引用されている（不足時は関連文献を紹介して引用を提案する）
- [ ] `\bibliographystyle` の書式が文献間で統一されている（著者名表記、DOIの有無）
- [ ] 著者名・年号・巻号・ページの記載が正しい（推測で補わず、確認できる場合のみ修正する）

### C. 図表

- [ ] 図表への本文参照が適切である（「図1に示すように」「表2に示す」）。図表は本文で初めて言及される位置に置かれている
- [ ] すべての図表が本文から参照されている（未参照の図表は削除を提案、または本文での参照を追加する）
- [ ] figure環境の配置指定は `[tb]`（または `[tbp]`）を使用し、`[h]` は使用しない
- [ ] 図表ファイルがサブディレクトリ（`./figures/`、`./tables/`）に保存されている
- [ ] キャプションが簡潔で、図表内の記号・単位の説明を含む
- [ ] 図の解像度・フォーマットが適切である（ベクタはPDF/EPS、ビットマップは300dpi以上）
- [ ] 軸ラベル・凡例の表記が本文の記号・単位と一致している

### D. 数式・記号

- [ ] 数式中の変数が本文（または記号表）で定義されている
- [ ] 数式の前後で「導入 → 数式 → 解説」の順に説明されている
- [ ] 数式の前後に不要な空行による段落分割がない
- [ ] 本文中の変数はイタリック（`$x$`）、単位・関数・略記はローマン体（`\mathrm{}`）で表記されている
- [ ] ベクトル・行列の表記が統一されている（太字 or 矢印、`\bm`/`\mathbf` の使い分け）
- [ ] 数式番号が連番で付与され、参照は `\eqref`（「式(1)に示すように」）でおこなわれている
- [ ] 次元解析の観点で式が正しい（左右の次元が一致する）

## 執筆支援の方針

- 文章の提案は必ず複数の選択肢（2〜3案）を提示する
- 修正理由を簡潔に説明する（「〜であるため、〜と表記する」）
- 専門用語は正確性を最優先する（誤訳・不正確な用語は指摘し、正しい訳語を提案する）
- 曖昧な表現は具体的な表現へ書き直す提案をする（例: 「適切に」「十分に」→ 数値・条件を明示）
- 原文の意図・事実・数値は変更しない（変更が必要な場合は著者の判断を仰ぐ形で提案する）

## Pitfalls

- 校正で数値・実験事実・著者の主張を変えてはならない
- ルールを機械的に当てはめ、文意を損なう修正をしない（例: 100字超の文を一律に分割して意味を壊す）
- 日本語論文のルール（である調・全角表記・`[tb]`）を英語論文に適用しない
- 有効数字・数値の丸めは著者の判断に委ね、提案にとどめる
- 図表キャプションと本文の単位・記号のずれは、双方を確認してから指摘する
- ビルドエラーを放置しない（修正後は必ず再コンパイルして確認する）

## Verification

- チェックリストA〜Dの全項目について、結果（OK／指摘）が記録されている
- 各指摘について「修正済み」か「提案のみ」かが区別されている
- 修正後の文書が `latexmk` でエラーなくPDFを生成できる
- 未引用文献・未参照図表・未定義変数が残っていない
